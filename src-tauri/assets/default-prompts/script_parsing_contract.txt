【系统 JSON 协议（最高优先级）】
1. 只输出合法 JSON，不要 Markdown 代码块、解释、标题或额外文本。
2. 必须保留下方根结构与字段，不得因分镜提示词改变外层 JSON 数据结构。
3. 分镜提示词可以自由规定 scenes[i].description 的内容结构、标签、顺序和排版。如果提示词明确规定或通过示例展示了每个分镜的文本格式，必须逐场遵循该格式，并将完整文本写入 description；不得将自定义字段提升为 JSON 字段。
4. 只有当分镜提示词没有规定或展示 description 格式时，才使用系统默认的完整时间轴镜头描述。
5. scenes[i].shotType 使用简洁、准确的中文描述镜头景别或构图；常用值包括大远景、全景、中景、近景、特写，但不限制于这些值。
6. scenes[i].cameraMovement 使用简洁、准确的中文描述运镜；常用值包括固定镜头、推进、拉远、摇镜、跟拍、环绕，但不限制于这些值。
7. scenes[i].environmentCaptureMode 只能是单视角或四视角；存在多视角、多机位或时间轴切镜时使用四视角，单一连续视角使用单视角。
8. scenes[i].setting.timeOfDay 使用准确的中文自然语言描述场景时段与光照状态，可参考黎明、早晨、白天、中午、下午、傍晚、夜晚，但不限制于这些值。
9. scenes[i].setting.era 使用准确的中文时代描述，可参考古代、民国、现代、近未来、架空；原文有明确朝代或世界观时直接使用更具体的描述。
10. scenes[i].characters[].emotion 使用符合当前表演状态的中文情绪描述，不限制固定词表。
11. 顶层 characters[].role 使用简洁中文描述角色在故事中的定位，可参考主角、反派、配角、龙套，但不限制固定词表；gender 使用符合原文设定的简洁中文描述，不限制固定词表。
12. scenes[i].dramatic.function 使用简洁中文概括本场戏剧功能，不限制固定词表。
13. 每个 duration 必须是数字并处于规定时长范围；totalDuration 必须严格等于所有 duration 之和。若 description 内也展示时长，两处必须一致。
14. 第一场 usePreviousLastFrameAsFirstFrame 必须为 false；只有时空、人物和动作连续时才可为 true。为 true 时填写 continuityLinkReason，否则使用空字符串。
15. 旁白同时写入 narration，并出现在 description 的用户自定义格式或默认时间轴中；真实角色对白只写入 description。
16. scenes[i].props 只包含需要维持视觉一致的真实道具；characters、setting、props、narration、duration 等系统字段不得因分镜提示词而缺失。
17. 若本集规划补充包含角色、环境或道具锚点，必须优先沿用；冲突优先级为：原文事实 > 本集规划补充 > 分镜提示词。
18. 禁止自行生成 @图片N、[图片N] 或其他引用编号。
