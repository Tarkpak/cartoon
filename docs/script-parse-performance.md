# 分集解析性能

长篇精品剧分集改为「全局轻量规划 → 分批并发生成 → 校验并合并」。前端接口不变，沿用现有流式进度展示。

- 正文至少 1400 字符且可以按完整行分成多批时启用；短文本、单行长文、科普拆解及显式指定 `maxScenes` 的请求保持单次解析。
- 原文按完整行分批，目标每批约 650 字符，不截断单行台词。所有批次原文拼接后与输入完全相同。
- 先生成统一视觉风格、导演节奏和角色外观；随后最多并发 3 批。每批携带相邻原文片段作为衔接参考，仅生成分配给自己的正文。
- 单批响应异常、分镜为空、描述或必要资产字段缺失、时长越界，或显式 Markdown 角色台词校验失败时，仅自动重试该批一次。成功批次在当前请求内保留。
- 合并按原文顺序排列，统一分镜 ID，角色按名称去重；每批首镜关闭上一镜末帧引用，避免对尚未生成的上一批末帧作出连续性假设。
- 输出使用紧凑 JSON；全局分析不再重复写进镜头，普通分镜不再强制生成十项戏剧分析。用户逐镜描述格式、对白和动作要求仍保留。

阈值和并发数位于 `src-tauri/src/backend/script_parse_pipeline.rs`。

## 观察效果

`raw.json` 样例正文约 2540 字符，会分成 4 批（666、664、659、551 字符），先执行一次全局规划，再以最多 3 路并发生成详细分镜。此为分段演算，不是线上耗时实测。

返回结果保留 `parseStrategy.chunkCount`，并在 `usage.parseTiming` 增加：

- `planningMs`：全局规划请求及其 JSON 解析耗时。
- `detailsMs`：详细分镜并发生成、校验和自动重试的总墙钟耗时。
- `batchCount`：详细生成批次数量。

每次模型调用仍通过现有日志链路记录，后续应使用相同正文和模型比较总耗时、各批耗时及对白覆盖情况。并发效果受供应商限流和排队影响；请求次数与重复输入增加，按调用次数计费时积分消耗也可能增加。

## 当前边界

台词程序校验覆盖 `**角色名**：台词` 形式，支持括号内表演提示和按标点分配到多个分镜；忽略标点、空白、括号内提示，检查台词片段是否按原文顺序出现。它不等于对所有自然语言剧情做语义完整性审查。

进度按批更新，分镜在全部批次成功后统一返回和写入；没有把未完成的部分结果写入项目。自动重试只在当前请求内生效，整次请求失败或页面断开后再次解析会重新生成，不支持跨请求断点续传。

## 进度与取消

进度状态记录任务类型、目标分集及开始/结束时间。切换分集后仍展示当前运行任务的真实标题；返回失败分集可继续查看其错误与耗时。阶段信息缺少批次计数时保留此前计数，心跳只进入日志。

切换项目、启动替代任务或卸载工作台时，通过 AbortSignal 关闭旧请求；读取错误事件或无效 NDJSON 时取消并释放 reader。后端请求内没有独立 spawn 的模型任务，连接断开或任一批最终失败时，仍在运行的请求 future 随解析流一起释放。

上游 SSE 必须收到完成原因或 `[DONE]`；提前 EOF、损坏事件、输出达到上限及过滤中断均按失败处理并记录日志。支持跨网络块 UTF-8、多行 SSE JSON，以及供应商忽略流式参数而返回完整 JSON 的兼容情况。

空分镜响应不会覆盖已有分镜。全部分镜生成后若项目保存失败，界面保留生成结果和保存错误，以便恢复保存；这不代表结果已成功持久化。
