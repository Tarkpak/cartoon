# 项目技能

设置 → 技能中心管理本机技能。工作台右上角“项目技能”直接进入当前项目的选择和执行记录。

## 使用

### 用写作技能润色对白

在线安装去 AI 味写作技能时选择“剧本／对白润色”（`script_polish`），然后在当前项目中启用。已有技能如绑定到分镜细化，需卸载后重新安装并选择新流程。

在工作台粘贴或拖入剧本，在生成分集目录之前点击“用技能润色剧本”。原稿和润色草稿并排显示，可以编辑草稿；点击“采用润色稿”后再生成目录、分镜与对白时间轴。“保留原稿”会丢弃草稿。失败不会覆盖原文；切换项目或修改原文会使旧草稿失效。

润色沿用剧本解析模型，允许修改对白措辞、句式和节奏，要求保留人物姓名与关系、剧情事实、事件顺序、关键线索和人物意图。模型无法保证事实完全不变，请在采用前核对。当前单次支持 6000 字以内的剧本，已有分集目录的项目不开放此入口，避免原文长度变化破坏分集边界；原文科普模式不开放润色。润色不会自动执行第三方技能附带的检查脚本。

### 安装和选择

1. 在“已安装”页面点击“本地导入”，选择目录或 ZIP。目录中需包含 `SKILL.md`。可直接安装仓库中的 `docs/skill-examples/cinematic-staging` 示例目录。
2. 查看技能说明、版本、流程、正文及参考附件。不兼容的技能显示具体原因，不能启用。
3. 在“已安装”列表左上角选择项目，打开所需技能的开关；底部出现保存栏后点击保存。新项目默认选择内置“分镜细化”和“视频审片”；自定义技能不会自动加入项目。
4. 剧情类剧本解析成功后执行分镜细化；视频审片由工作台审片入口执行。原文科普模式不执行分镜细化。更改只影响后续执行，不自动重写已有内容。
5. 点击列表右上角“执行记录”，在侧栏查看技能版本、状态、结果摘要和错误。模型的完整结果仍在原分镜或审片界面展示。

技能行的“更多”菜单可以查看详情、在本机停用或卸载技能。版本、来源、正文和附件收在详情侧栏，格式说明在右上角帮助入口。“本机停用”对本机所有项目生效。项目未勾选任何分镜细化技能时，跳过细化；未启用任何审片技能时，审片入口会提示启用。卸载自定义技能会清除各项目对它的选择，保留历史记录和已生成内容。升级版本请先卸载再安装，并重新选择项目。

## 格式

```markdown
---
name: cinematic-staging
description: 展开站位、动作与光线
version: "1.0.0"
stages: [scene_detail]
---
技能正文，写明创作或审查要求。
```

- `name`、`description`、非空正文必需；`version` 建议使用带引号的版本字符串。
- `stages` 可包含 `script_polish`、`scene_detail`、`video_review`。缺少或包含未知流程时可安装查看，但不能启用。格式不合法时拒绝安装。
- 完整保留 UTF-8 文本附件，包括 Python 脚本、YAML 配置、LICENSE 和 VERSION。运行时仅将正文和 Markdown、TXT、JSON 参考资料传入模型；`scripts/`、`agents/`、`dist/` 下的文件只保存供查看，不注入模型。当前参考资料统一提供给模型，由模型按任务应用相关规则，不支持动态读取或分阶段加载附件。
- 每包一个 `SKILL.md`，可包在同一顶层目录中。最多 128 个文件，解压后文本合计 1 MB，单文件限 256 KB，ZIP 上传最多 1 MB。Finder 生成的 `.DS_Store`、`__MACOSX`、`._*` 元数据自动忽略。单个项目每个流程的技能正文与参考资料（包含包装提示词）合计不得超过 96 KB。技能包存储与模型上下文独立计量；脚本和工具配置不占运行上下文。分镜细化保留原有 48,000 字节的场景和导演要求预算，另加已校验的技能上下文；其他解析流程的预算不变。不截断超限内容。
- 此版本执行声明式文本技能，不能执行 shell、Python、Node、MCP、外部工具或 hooks。声明 `allowed-tools` / `tools` / `mcp` / `hooks` 的包仍会标记不兼容；仅附带脚本或工具配置不会阻止安装和启用，详情会提示这些附件仅保存、不执行。第三方 Skill 并非全部即装即用。
- 导入不读取服务器任意路径，不解压到磁盘，不运行包内代码。ZIP 越界路径、符号链接、重复路径和超限内容会被拒绝。

## 执行与存储

分镜细化沿用原有分组、并发、重试、时间轴和对白校验，只复制校验通过的描述，不允许 Skill 改写角色 ID、资产、集归属或总时长。审片使用视频的三张真实抽帧；口型、对白音频和完整动作属于未验证项。生成权限仍由原工作流检查。

技能包、启用状态和按项目的选择保存于本机 SQLite `system_config.workflow_skills_v1`，不参与项目协作同步；同一设备用户共享安装目录的语义。项目选择修改需要项目编辑权限，查看选择与记录需要查看权限；这是本机执行偏好，不申请协作对象编辑租约。协作成员需在自己的设备安装和配置技能。

执行开始时固定选中技能及版本；切换、停用或卸载不会修改已开始的执行。`skill_runs` 保存每个项目最近 100 条记录（仍在执行或等待同步的记录不清理）。失败、取消会写入状态；应用重启会将遗留的执行中记录标为中断。没有额外的凭据配置，模型沿用对应工作流设置。

不需要环境变量或云端迁移；本机数据表首次启动自动创建。前端与 Rust 后端需一同更新。

## 在线检索和安装

在技能中心切换到“发现技能”：

1. 输入关键词搜索 skills.sh，或直接粘贴来源。支持 `https://skills.sh/owner/repo/skill`、`owner/repo@skill`、GitHub 公开仓库链接，以及 `tree/分支/技能目录`、指向 `SKILL.md` 的 `blob` 链接。仓库内有多个候选目录时需选择具体技能。含 `/` 的分支名请改用提交 SHA 链接。
2. 查看技能正文、附件、来源与固定提交版本。在线预览与安装均支持单文件 256 KB、合计 1 MB、最多 128 个文件。包含不兼容的工具声明时仍可查看，并显示具体原因；仅附带可选脚本不会阻止安装。选择流程时另外校验实际模型上下文的 96 KB 上限。预览不会运行包内代码。正文或附件检测到常见命令用法时会另外提示仅作文字参考；此提示不代表能够执行命令，也不能代替检查技能的真实依赖。
3. 选择“剧本／对白润色”、“分镜细化”和/或“视频审片”后安装。此选择保存在本机配置中，不要求修改作者的 `stages` 字段；原始 SKILL.md 同时保留供查看。请检查技能内容确实适用于所选流程；工具依赖不能仅靠流程绑定变成可执行能力。
4. 安装后自动返回“已安装”。选择项目、打开技能开关并保存。在线安装不会自动修改任何项目选择。

搜索来自 skills.sh 当前 CLI 使用的搜索接口，下载来自 GitHub 公开仓库。搜索结果仅显示可识别的 GitHub 来源；安装量不代表质量或兼容性。第三方接口可能限流或变更，失败时可重试或使用本地安装，不会把请求失败显示为“无结果”。不需要 Node、Git 命令或 GitHub Token。

预览固定 Git 提交 SHA，并缓存该版本实际下载的文件 15 分钟（本机进程最多保存 32 份预览）；安装只读取服务端预览，不接受浏览器重新提交的文件、下载地址或来源信息。预览过期、被新预览替换或应用重启后需重新预览。来源记录包含仓库、目录、提交、内容摘要和安装时间；执行记录也保留来源版本。相同仓库目录不允许重复安装，不同来源的同名技能可并存。首版不自动升级或覆盖已安装版本，更换版本或流程绑定需先卸载再安装。

网络请求只访问固定的 skills.sh、GitHub API 和 GitHub 原始文件域名，禁止重定向到其他地址。限制响应大小、下载时长及并发；不解压整个仓库、不读取本地路径、不执行 CLI。符号链接、子模块、截断的仓库目录、超限技能和非 UTF-8 附件会明确报错。纯文本 `LICENSE`、`NOTICE` 可以随包保留。

`kkkkhazix/human-writing@human-writing` 可直接在线安装，建议绑定“剧本／对白润色”。完整保存原始正文、参考资料及检查脚本；写作规则与参考资料参与润色，附带的 Python 文稿检查器不会自动执行。分镜细化仍保留对白，不用于修改台词。

## 技能执行与模型日志关联

- 客户端技能中心选择项目后，打开“执行记录”：显示技能名称、固定版本、执行状态、耗时与同步状态，点击“查看模型调用”筛选本次执行的全部请求。
- 客户端“大模型日志”支持按技能名称/ID、技能执行编号筛选。详情显示技能列表、流程；分镜细化还显示第几镜至第几镜以及尝试次数。同一执行的多个批次和重试共享执行编号。
- 后台“日志 → 技能执行”显示各账号上传的执行记录，包括调用模型前失败、跳过和中断的记录；可按技能、状态查询，查看技能来源版本并跳转关联调用。“调用日志”也支持按技能、执行编号筛选，并可返回执行记录。
- 技能执行记录单独同步，不产生额外模型调用或计费。上传只包含执行元数据和结果摘要，不上传技能附件包。实际模型请求仍沿用现有模型日志同步。
- 离线或后台未更新时记录留在本机等待同步，每 30 秒重试；按执行时的账号隔离，切换账号不会上传前一个账号的记录。重复和乱序上传不会把终态退回“执行中”。后台模型调用数量只统计尚未归档的可查看日志，模型日志与技能记录独立同步，数量可能短暂滞后。
- 历史模型日志没有可靠关联编号时保持原状，不从提示词猜测或补造关联。本机旧技能记录标为“本机记录”。

需要同时更新客户端 Rust 后端和管理后台；两端 SQLite 启动时自动添加日志字段，后台自动创建技能执行记录表，无需手动迁移。云端部署前客户端会保留待同步记录，后台更新后自动补传。
