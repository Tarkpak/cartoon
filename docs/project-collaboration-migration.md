# 从项目快照同步迁移到按集协作

## 当前状态

现有工作台默认仍使用整项目快照和项目租约，不会自动迁移用户项目。
第二阶段已经实现云端独立对象、事务式迁移、按对象租约、版本校验、幂等写入、增量读取，以及 Rust 转发接口。
已接入独立的按集协作编辑页，支持项目名称／简介／画幅、集数正文、分镜文本／新增／删除／排序和公共角色分别保存、增量刷新及草稿恢复。集数目录新增、删除和排序通过原子资源组保存。项目成员管理与删除也已改为独立云端操作。单集正文已接入“生成预览 → 版本复核 → 采用到草稿 → 单集保存”；分镜首帧与视频已接入独立结果预览和手动采用；项目列表已提供所有者／管理员可用的迁移预检入口，线上试点需指定项目后执行。

已落实的第一阶段：

- 交互请求等待全局云同步锁最多 5 秒，超过后返回可重试错误。
- 后台项目重试逐个项目释放锁，避免整个批次阻塞交互。
- 冲突读取云端版本的总预算为 45 秒；返回备份前重新取得有效租约。
- 冲突窗口每 20 秒续租，关闭后释放；前端请求有超时且禁止自动重试写请求。
- 请求失败后清除当前可提交的备份引用，要求重新核对。磁盘备份仍保留。
- 拉取云端快照之后再次校验编辑权，防止读取期间租约失效后替换本地。

锁等待超时不代表已经开始的操作被撤销。客户端请求超时后必须重新读取状态，不能直接重放覆盖请求。

## 现有数据约束

- `scripts.parsed_data.episodePlan` 是集数目录。
- `scripts.parsed_data.writingStudio.episodes` 保存剧本创作工作区的每集正文。
- `scenes.episode_id` 标识分镜所属集数。
- 工作台 `buildProjectSaveBody()` 会提交所有集数、分镜和人物。
- `api_project_put_inner()` 在事务内删除并重建该剧本所有分镜，以及项目所有人物。
- 生成任务保存项目级 `projectEditLease`，后台回写和续租也以项目为单位。

因此，不能先解除项目锁再继续使用现有保存接口；否则不同集数的过期页面也会相互覆盖。

## 第二阶段：独立对象与版本（已实现）

新增独立的集对象，稳定 ID 沿用已有 `episodePlan.id`，将对应正文和分镜映射到同一集。
项目设置、集数目录、每集正文与分镜、公共人物资源分别保存。集数排序使用目录顺序，不能以显示集数作为身份。
没有 `episodeId` 的历史分镜迁移到一个明确的默认集；重复或不一致的集 ID 必须报错，不静默丢弃数据。

每个对象使用单调递增的整数 `revision`，写入携带 `expectedRevision`。
云端在一个事务中检查权限、租约和版本，再修改对象并记录变更。
两个成员写不同集互不影响；写同一对象时只返回该对象的 409，其他集继续可用。
删除保存墓碑，避免离线客户端重新上传已删除内容。

云端初始化自动创建五张表：`project_collaborations`、`project_collaboration_resources`、`project_collaboration_leases`、`project_collaboration_operations`、`project_collaboration_changes`。
原快照完整保存在 `project_collaborations.source_snapshot_json`，不受旧快照保留数量影响。
Rust 在迁移前另写本地 `project-collaboration-backups/` 备份；有本地待同步内容、同步冲突或未结束生成任务时拒绝迁移。
迁移仅限所有者或系统管理员，且需原协议的有效租约与已核对云端版本。迁移事务失败时不留下部分对象。

集对象保留 `plan`、`writing` 和 `scenes`，项目设置保留其余剧本字段和快照附加信息。
迁移保留稳定 ID、媒体地址、公共人物和项目附加字段。不同来源的集 ID、序号或分镜引用有歧义时拒绝迁移。
目录定义集数顺序。新增或删除集时必须在同一写入事务中更新目录，并同时持有对应对象与目录租约。
集内分镜不能引用其他集，所有集中的分镜 ID 必须唯一。

### 接口约定

- 云端：`POST /api/client/project-collaboration`，携带 `ownerUserId`、`localProjectId` 和 `action`。
- Rust：`POST /api/project/{id}/collaboration`，只需 `action` 和操作参数；后端从本地项目、账号和窗口上下文补齐身份，租约 token 不返回浏览器。
- `read`：返回 `enabled`、`protocolVersion`、一致性游标 `cursor` 和对象列表。当前协议版本为 1，迁移后初始对象 `revision = 1`。
- `enable`：迁移现有云端快照。Rust 先确认没有未同步修改或任务，再获取项目租约。响应丢失后再次调用会先读取迁移状态，避免重复迁移。
- `lease`：参数 `type`、`id`、`leaseAction`，支持 acquire / heartbeat / check / release / takeover。窗口间和资源间分别缓存，租约有效期为 90 秒；协作页每 20 秒续租，前端每秒检查是否过期。
- `write`：参数 `operationId` 和 `mutations`，单批 1–100 项；每项包含 `type`、`id`、`expectedRevision`、`body`。新对象的基础版本为 0，删除使用 `body: null`。Rust 自动补齐 token。
- `changes`：参数 `after` 为上次增量读取游标，返回 `changes`、`cursor`、`hasMore`，按序分页。删除也会返回墓碑。
- `members`：按云端权限读取所有者、规范化成员记录和当前账号权限；Rust 更新本地成员缓存。
- `memberPut` / `memberRemove`：需要 `manage_members`，不要求编辑或资源租约。携带 `userId` 和成员当前 `expectedUpdatedAt`；新增成员时后者为 `null`。修改还携带 `role`、`permissions`，账号名称从云端用户表获取。
- `delete`：需要 `delete`，云端软删除项目、撤销全部资源租约，保留迁移备份、资源和提交记录；重复删除返回原删除结果。Rust 收到明确成功后才清理本地项目并记录墓碑，不加入旧删除同步队列。

版本冲突与租约失效分别返回 409、423，响应 `data` 包含受影响对象的 `type`、`id`，以及适用的 `revision`、`deleted`；Rust 只转发这些对象定位字段。

`write` 响应的游标不能直接替代客户端的增量读取游标：中间可能还有其他成员的修改，需要继续按原游标补拉。
同一个账号的操作 ID 只能对应一份内容；相同内容重试返回原结果，不重复加版本或记录变更。
租约 token 不参与操作内容指纹。云端先查已完成操作，再校验当前租约，允许响应丢失后在租约过期时获取原结果。
Rust 发送前在本地持久化操作，重试保留原操作 ID、内容和租约。窗口、账号、项目分别隔离；新操作仍需要有效租约。
明确收到 409 或 423 后应重新读取对应对象、重新取得编辑权，并以新的操作 ID 提交核对后的内容。

兼容项目详情、账号数据和管理员查看接口会从对象重建只读快照。旧的整项目上传与项目级编辑租约对已迁移项目关闭。
已迁移项目的成员查看、修改、移除及项目删除通过独立管理操作处理，旧协议保持关闭；未迁移项目沿用原有管理流程。
协作对象的 423 不再触发前端的整项目“编辑权丢失”事件。

## 第三阶段：按集编辑与保存（基础编辑页已接入）

租约范围为 `(ownerUserId, projectId, resourceType, resourceId)`，其中 `resourceType` 包括集、目录和公共资源。
每个本地租约缓存也必须包含该范围，不能继续用一个项目配置项存储全部租约。
集数负责人属于项目权限之下的分工限制，不能单凭负责人字段提升账号权限。

客户端明确选择要编辑的集。保存只提交该集的正文和分镜，不提交其他集的缓存。
公共人物修改使用独立操作和资源租约；跨集移动分镜需要校验来源与目标两个范围，并在一个事务中提交。
整项目设置和目录调整保留独立的管理操作。

## 第四阶段：生成任务与增量更新（正文、分镜首帧与视频预览已接入）

单集正文通过 `/api/script/write` 的协作分支生成，只允许 `episode_draft`。开始生成时，Rust 使用当前窗口的资源 token 调用云端 `generationCheck`，同时检查 generate/edit 权限、集 revision、设置 revision 和集租约。模型上下文由已核对的云端设置与本集大纲／正文构造，不读取旧本机快照，也不信任浏览器传入的整份上下文。

结果先保存在本机 SQLite 配置中，按项目与账号隔离，最多保留最近 20 次；`GET /api/project/{id}/collaboration/draft-results` 在线复核查看权限后返回结果。结果持久化完成后才响应生成请求，因此响应丢失时可刷新结果恢复。请求不自动重试，避免重复模型费用；进程在模型完成前退出不视为已完成任务。生成不会修改云端资源，窗口可继续编辑；采用前再次检查云端输入版本、编辑权和本地草稿，仅写入该集 writing.draft／continuityNotes，再由用户确认保存。输入已变化时保留结果供导出／手动合并。

分镜首帧通过 `POST /api/project/{id}/collaboration/scene-image` 生成，使用版本核对后的云端分镜及项目设定和当前首帧流程模型。结果按账号／项目保存在本机，最多 20 次，通过 `GET /api/project/{id}/collaboration/media-results` 读取。

视频沿用 `/api/video/generate` 的协作分支。配置由已核对的云端描述、首帧、时长及项目画幅构造，使用当前视频流程模型；任务 config 持久化 `collaboration`，包括 actorId、projectId、episodeId、sceneId 和输入版本。任务创建不获取旧整项目租约；完成后仅写 `video_tasks` 的结果和状态，禁止写旧分镜、旧生成视频关联表或排入旧整项目同步。自动语音提取只生成候选，不直接回写公共资源。媒体结果接口返回当前账号在本项目最近 30 个视频任务，状态刷新复核账号及云端查看权限，租约失效不丢弃已生成的媒体。

媒体采用先复核云端输入版本和集租约，再复核当前草稿及目标分镜是否仍在该集；只修改目标 firstFrame/referenceStatus 或 videoUrl/videoStatus。替换视频时保留旧视频历史并清除旧视频的 lastFrame，避免后续连续帧引用过期画面。采用仅加入单集草稿，由用户检查后按资源版本提交。生成过程不自动写云端，结果过期、分镜被删除／跨集移动时可继续预览／导出。采用共享资源要求 HTTP(S) 共享地址；本机 `/api/image/file`、`/api/video/file` 等路径只允许本机预览，需配置共享存储后再生成与采用。

客户端按云端变更游标拉取对象更新，仅刷新没有本地未提交修改的对象。
离线修改保存为本地待提交操作，每条包含稳定操作 ID、对象范围和基础 revision。
云端必须幂等处理重试：同一操作不重复执行；同一操作 ID 携带不同内容时拒绝。
联网恢复后逐项提交，冲突停留在对应集或资源上，不冻结整个项目。

## 发布与回归门槛

先发布兼容的数据迁移和能力查询，再发布新客户端。只有所有写入口和后台任务都支持范围校验后，才能开放多人编辑。
进入协作模式的项目必须拒绝旧版整项目写入，包括旧客户端、后台重试和冲突覆盖入口。
旧快照保留为迁移备份与导出材料。发布前对真实项目副本演练，核对每集正文、人物引用、分镜数和媒体地址。

必须覆盖的双客户端场景：

1. 甲保存第 1 集，乙保存第 2 集，两者成功且双方内容完整。
2. 同一集争抢、接管、租约过期，以及接管后旧页面和旧任务延迟回写。
3. 修改公共人物时其他成员编辑集数，不发生人物列表整体替换。
4. 删除集或分镜后，离线操作和迟到任务不能复活已删除数据。
5. 请求已提交但响应丢失后重试，不重复执行或覆盖新版本。
6. 历史项目迁移、失败回滚、旧客户端拒写，以及本地未同步修改恢复。

### 客户端状态层（尚未开放迁移入口）

新增 `app/lib/project-collaboration-client.ts` 和 `useProjectCollaboration` 会话封装：

- 按资源保留基础版本和草稿；增量更新不会覆盖未保存内容，冲突只标记对应对象。
- 只有变更流推进游标，保存响应和单对象冲突处理不会跳过其他成员的更新。
- 不确定的写入结果保留原操作 ID 和原请求，重试不会夹带之后输入的内容；409/423 保留草稿并要求处理冲突。
- 会话按资源取得编辑权，每 20 秒续期和轮询；编辑权丢失时备份草稿，退出时释放持有的资源。
- 单对象冲突可重新读取并显式选择保留本地或采用远端；远端删除的对象不能用旧草稿直接复活。

### 已接入的协作编辑页

路由为 `/projects/:id/collaboration`。云端拉取项目摘要或导入快照时记录协作模式（要求本地项目所有者匹配），即使本地旧快照未变化或有未同步修改，也会停用旧写入入口。项目列表点击已知协作项目直接进入此页；资产工作台和剧本工作台的编辑权提示也显示“进入按集协作”。已记录协作模式的本地项目，即使当前用户只有查看权限，也返回正确的模式提示。本地旧协议待同步数据仍保留在原数据库中，不自动合并到新的资源草稿；迁移前仍需核对所有参与设备。

- 集数选择遵循目录顺序；标题、梗概、正文和该集分镜文本在同一个集对象中提交。
- 集数目录可新增、删除和上下排序（至少保留一集）。新增／删除同时提交目录与集对象；排序同时更新目录、受影响集的目录序号、正文序号及分镜所属集序号。仅获取受影响集的租约，存在草稿或被他人占用时不调整。
- 跨集移动将原分镜移到目标集末尾，保留分镜 ID、媒体和历史字段，同时更新集归属；目录、来源集、目标集作为一组提交，先检查双方草稿与租约。
- 目录调整作为一组草稿备份；新建集使用基础版本 0，未知提交结果沿用原操作 ID 重试。整组失败后可查看远端版本并放弃本次调整，不影响其他对象草稿；放弃前再次检查远端版本。
- 公共角色单独选择、取租约和保存。补丁保留未编辑字段、媒体 URL 和扩展元数据。
- 未取得编辑权时只读。切换对象时释放前一对象租约，草稿继续保留；迟到续租不能恢复已释放的编辑权。
- 草稿即时保存到按账号和项目隔离的 `sessionStorage`，只存有修改的对象，不复制其他集。刷新同一窗口后可显式恢复或导出备份；恢复发现版本变化时标记冲突。关闭窗口后不保证浏览器继续保留该备份，需要长期保存时应导出 JSON。
- 结果不确定的提交保留原操作 ID；重试确认按钮会向后端核对原提交，不能通过取租约失败推断原提交没有成功。
- 冲突先展示远端正文，再选择采用远端或保留本地草稿。确认时再次核对已展示的版本，远端再次变化则要求重新查看。
- 备份存储失败时提示并阻止直接离开；保存成功或导出当前草稿后可离开。账号切换后关闭当前会话。

此页已支持跨集移动分镜，以及单集正文、分镜首帧、视频生成预览与手动采用。公共角色图片与道具已接入生成预览和手动采用。自动语音候选和离线提交队列已接入；真实 HTTP 服务的多账号迁移演练已通过，线上真实项目试点仍待指定项目／账号后执行。旧入口继续拒写，不自动迁移现有项目。

### 协作项目管理

协作编辑页提供“成员”入口，项目列表原有成员弹窗和删除操作也复用新协议。权限变更不提交任何集数或项目快照，不更新本地项目为待同步状态。

成员弹窗和删除请求设有 30 秒超时并禁止自动重试。全局确认框使用高于普通弹窗的独立遮罩与内容层级，避免在成员弹窗内移除时被底层遮罩拦截点击。

成员更新与移除在云端事务中核对成员版本，版本过期返回 409。重复提交相同权限或重复移除已不存在的成员不会再产生变化。普通成员管理员不能授予超出自己已有范围的权限，不能修改所有者或移除自己；所有者和系统管理员仍拥有全部项目权限。目标账号必须存在且处于启用状态。

权限变更或移除后立即撤销目标成员的资源租约；所有资源读写仍由云端按当前成员关系再次鉴权。项目删除后所有协作读写返回已删除，旧页面和迟到提交不能继续写入。成员版本与项目同步时间保持递增，避免成员与集数在同一毫秒提交时被旧的快照拉取判断漏掉。

### 客户端回归

`bun x vitest run app/lib/project-collaboration-client.test.ts app/lib/project-collaboration-editor.test.ts app/composables/useProjectCollaboration.test.ts` 覆盖按对象保存、响应丢失重试、草稿恢复校验、远端再次更新、独立租约失效、过期和迟到续期。

`bun scripts/check-project-collaboration-browser.mjs` 在已运行的 `bun run dev:frontend` 上执行模拟接口的浏览器回归；需要已安装 Playwright 和 Firefox。可用 `PLAYWRIGHT_MODULE` 指定已有 Playwright 模块路径，`COLLABORATION_QA_URL` 指定开发地址。脚本拦截全部 API 请求，不修改真实项目，验证集数和角色独立提交、媒体保留、刷新恢复、远端冲突、成员修改与移除的版本参数，目录增删排序的原子提交、集数锁冲突拦截、整组冲突放弃、跨集移动媒体保留、正文／首帧／视频预览不写资源、媒体任务状态刷新、旧视频历史保留、结果刷新恢复与过期输入拒绝采用，以及窄屏布局，并将截图写入系统临时目录。

公共资产图片接口 `/api/project/{id}/collaboration/asset-image` 从云端核对后的角色或设置读取生成描述；角色使用独立角色租约，道具使用 settings 租约，不借用集数租约。道具必须具有唯一标识。结果按账号／项目持久化，不自动写回。采用时再次核对资源与设置版本，只修改目标角色 baseImage 或目标道具 referenceImage；本地专属媒体地址拒绝采用。公共资产与分镜共享结果列表，但各自筛选结果类型。

### 自动语音候选

协作视频 config 中持久化经云端验证的分镜、公共角色资源版本和设置版本。后续视频生成只从这些公共音色构造音频参考，不读旧本地人物表。视频完成后，自动提取对白与旁白音频，按账号／项目保存 `asset-voice` 候选；不会获取公共资源租约或自动覆盖音色。公共角色／项目设置页可试听并采用，采用需对应资源租约和原输入版本，保留图片和其他字段，已有锁定音色拒绝替换，首次采用自动锁定。视频任务保留提取状态，失败或中断超过十五分钟可手动重试；重试复核来源集版本和租约。候选以来源任务／目标生成稳定 ID，重复处理不会重复插入同一候选。音频上传到共享存储后才能采用。

### 离线自动续传

仅点击保存的提交会进入自动队列，普通未保存草稿不会自动上传。前端先生成操作 ID 和准确载荷，再写入按账号／项目／操作隔离的 localStorage；本机后端仍保留持久化 outbox。网络错误、超时及服务错误保留原提交，online 事件及每二十秒心跳会尝试重新获取对应租约并重放原操作；服务已提交时，即使原租约失效也先确认原回执。关闭窗口后重新打开同一账号／项目可恢复队列，不同窗口的操作不会互相覆盖；多个队列逐项恢复，发现冲突或权限拒绝即停止该操作。冲突草稿继续持久化，后续恢复需手动审阅。存储失败时不发送未持久化的新提交。未取得编辑权时不会开始新的在线编辑。

### 迁移入口与服务演练

项目列表向所有者／管理员显示“按集协作”。先检查本地同步状态、活动生成任务和云端资源结构，再展示集／分镜／人物数量；预检不写协作数据。用户核对并确认后，启用请求必须携带已展示的版本与 SHA-256 快照摘要。确认时重新校验并保留本地备份、云端原始快照；版本或摘要变化则拒绝迁移。响应丢失后重新预检可识别已完成迁移。

运行 `bun backend/scripts/check-project-collaboration-http.ts` 可复现隔离演练。脚本启动真实 H3 HTTP 接口，使用正式认证逻辑、真实磁盘 SQLite 和两个独立客户端，验证所有者迁移、旧整项目同步拒写、不同集并发保存、同集互斥、增量刷新、媒体保留、回执丢失后接管与原操作重放、服务断开／重启后的离线续传以及原始备份保留。脚本仅使用新建临时目录，结束后清理，不读取或迁移已有项目。此验收未包含生产服务器、两台真实设备或真实 ASR／视频供应商调用。

加上 `--local` 可执行完整本地桥接验收：先运行 `cargo build --manifest-path src-tauri/Cargo.toml --bin playlet-backend`，再运行 `bun backend/scripts/check-project-collaboration-http.ts --local`。脚本启动所有者、成员 A、成员 B 三个独立 Rust 后端，各自具有独立数据库、设备身份和公共目录，连接临时云端 HTTP 服务。验证真实本地迁移备份、跨本地后端并发编辑、增量刷新、同集互斥、本地进程重启／窗口变化后的原回执确认，以及未提交操作在获取新租约后的续传。本机 outbox 以账号／项目／操作 ID 为稳定键，兼容旧窗口键；重连可更换租约凭据，但不允许改变原内容和基础版本。服务演练子进程仅在临时目录运行，使用显式环境变量，不加载工作区 .env 或真实账号凭据。
